B1 alternative candidate: Ternary-Bonsai-2-4B Q2_0. CPU-only exploratory check on the VENTUNO Q board with upstream
llama.cpp ff5a2337, done 2026-10-19, plus its size on one NPU session. Not an NPU stage, not a campaign run.

Why (the owner, 2026-10-19: "Ok to look for smaller that fit ... and ok to see what new in the new version")
  The Bonsai-2 family (prism-ml on Hugging Face, checked 2026-10-19): 27B (Qwen3.8-27B based) ships only PQ2_0 and
  PTQ1_0 (5.9-7.2 GB), which upstream llama.cpp and ggml-hexagon reject (PrismML fork, CUDA/Metal/CPU), so it is out
  for the NPU now. 9B, 4B and 2B ship a Q2_0 file that upstream runs. The 4B (Qwen3.5-4B based, same qwen35 hybrid as
  the 9B: 24 linear-attention, 8 full-attention layers, tied embedding/LM head) fits one NPU session, so it avoids the
  multi-session split and stays well below R2's suspected per-session limit.

Size on one NPU session (table-bonsai2-4b-q2_0.txt/.tsv, tools/gguf_tensor_table.py, header only, ctx 8192)
  201 Q2_0 tensors (4,200.9 M params) and 225 F32. The tool's NPU allocation is 1,145.43 MiB: the 32 blocks plus the
  output layer, which is the tied input embedding duplicated (170.5 MiB); the input embedding itself (170.5 MiB) on
  the CPU. KV at ctx 8192: 256 MiB F16 (8 attention layers); at 16384: 512 MiB.
  HTP0:0 at ctx 8192: weights 1,145 + KV 256 = 1,401 MiB before recurrent state and compute (at 16384: 1,657 MiB).
  Against R2's refused map at 2,144.55 MiB in one session (suspected limit, not isolated): about 740 MiB of room at
  8192, about 490 MiB at 16384, before compute buffers (R2's sessions logged 60-101 MiB).
  Unverified placement question: with -ot 'token_embd\.weight=CPU' (as B1c's command uses), the tied output copy may
  also be overridden to the CPU, since the duplicate carries the same tensor name; then the NPU holds about 975 MiB and
  the LM head runs on the CPU. Which buffer the copy lands in is a load observation, not a fit claim (by buffer
  identity in the log); a 4B load stage would state its expected placement and check it.

Not claimed: anything about the NPU, the publisher's quality figures, campaign fitness, or that the 4B and the 9B are
equally good: T5 checks single tool calls only, and both pass it. A 4B NPU load would be a new stage (B1c-4B) with its
own reviewed command, budgets and PASS conditions, run only on the owner's approval.
