       scheduler skips FLASH_ATTN_EXT in its weight rule (ggml-backend.cpp :1107), so with -fa on the attention could

Stopping (review of 09a7a43; the wrapper's contract and plan section 7)
  STOP: a wrapper verdict STOP (timeout, floor, stall, orphans, interruption, a DSP or kernel fault, a refused map, a
     watchdog intervention, missing or failed evidence) ends the stage: no later run or option starts, nothing is
     retried or recovered automatically, and the owner decides. The same for an identity record that changed.
  Rejection: an option fails acceptance cleanly when its wrappers report PASS or FAIL (the command failed, nothing
     else wrong: e.g. T5 below 18 or a speed depth not measured, which make the payload fail) and a-f below is not
     met. A rejected option's remaining run is not started (first failure; a parity rejection skips its server run),
     and the next option runs.
